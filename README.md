# mlphibroker

MATLAB utilities that run **inside the PHI zone** (the MATTA workstation) and turn a heterogeneous
DICOM export tree (dynamic PET, CT, MIM RTSTRUCT ROIs) into **Safe Harbor** NIfTI and JSON files
ready for kinetic analysis: canonical subject and random session codes, every time expressed as
seconds from scan start, the decay-correction contract stamped, no calendar date, clock time,
name, serial, institution or UID anywhere in a file name, header or sidecar.

This repository is public and contains **no PHI**: only code and a fabricated synthetic DICOM
fixture (`test/fixtures/synthetic_dicom`, generated by `tools/make_synthetic_dicom_fixture.py`).
It is the enclave-side companion of the `idif2026` SPEC-PHIBROKER work order **WO-0002**; it is a
fast working example for time-sensitive analyses, not the broker's enclave ETL, and phase 1 of
SPEC-PHIBROKER releases no images to Claude Code. Outputs stay in the PHI zone until the
investigators review them.

## Quick start (on MATTA)

Four PHI-side files are involved, all kept in the PHI zone and never committed (`*_PHI.*` is
git-ignored). Edit CSVs only in a **text editor** (Notepad++, VS Code, or MATLAB `readtable`/
`writetable`); Excel strips leading zeros from ids, re-types dates and can drop the header row.

```matlab
addpath('C:\Users\<you>\Documents\MATLAB\mlphibroker\src')
root    = 'D:\MIM\MASH\2026-10__Studies';          % the PHI DICOM tree: any depth, mixed folders, many persons
outRoot = 'D:\MIM\MASH\safeharbor_2026-10';         % PHI-side until the investigators have reviewed it
```

**Step 1. Roster: who is who.** One row per person found in the tree, `Subject` empty.

```matlab
mlphibroker.Crosswalk.rosterTemplate(root, 'D:\MIM\MASH\roster_PHI.csv')
```

Fill `Subject` with the **study coordinator's code** for each person (for MASH, `sub-ECL1i005`
style; for CCIR_01211, the key-vault `sub-108xxx`). The coordinator assigns codes at first contact
and contacts that never enrolled leave gaps, so codes cannot be reconstructed from an export; the
roster is the authority. A person exported under several `PatientID`s appears once (ids joined
with `|`). Leave `Subject` empty for a person you cannot yet code: that person is refused later,
never guessed.

**Step 2. Crosswalk: which study is which visit.** One row per study, with proposals to authorize.

```matlab
mlphibroker.Crosswalk.template(root, 'D:\MIM\MASH\crosswalk_2026-10_PHI.csv', ...
    struct('Roster', 'D:\MIM\MASH\roster_PHI.csv'))
```

`Subject` comes from the roster. `Session` is proposed as `ses-NN`: studies of one person on one
`StudyDate` are one visit and share a `Session` (a dynamic and a delayed scan of one injection;
their outputs are told apart by `run-01`, `run-02` in acquisition order); distinct days get random
ordinals, so `ses-01` is not necessarily the earliest visit (SPEC-PHIBROKER §4.2). The `Note` column
says why each value was proposed, and `<file>.README.txt` repeats the rules. Authorize by leaving
the values, or edit `Subject`/`Session` only. Re-running the template regenerates the same
proposals (seeded), so edit the roster rather than the crosswalk for anything you want to keep.

**Step 3. Deny list: names that must not appear anywhere.** Built from every name-bearing header
field in the tree (patient, operators, physicians, institution, station, ids), split into words,
plus the names you add (coordinator, investigators, anyone who might appear in free text).

```matlab
mlphibroker.SidecarPolicy.denyListTemplate(root, 'D:\MIM\MASH\deny_names_PHI.txt', ...
    {'Coordinator Lastname', 'Investigator Lastname'})
```

To see what the headers actually hold before deciding on extra names (PHI-side console only):

```matlab
mlphibroker.DicomTree.inspectNames(root)                 % PET, CT and RTSTRUCT: person-name and free-text fields, ROI names and interpreters
mlphibroker.DicomTree.inspectNames(root, {'rtstruct'})
```

Review the file (one entry per line; entries under three characters are ignored; matching is
case-insensitive on whole words). Person-name fields are split into words; ids, institution and
station are whole strings. A hit in an output name or sidecar quarantines that pair. To see, on
the PHI side only, which key and which entry caused a quarantine:

```matlab
mlphibroker.SidecarPolicy.explainQuarantine(outRoot, 'D:\MIM\MASH\deny_names_PHI.txt')   % prints matched values: never paste outside the PHI zone
```

Secondary captures (dose reports, screen saves, MIPs) and localizers are never converted, because
text may be burned into their pixels; the report counts them as `secondary` / `localizer`.

**Step 4. Convert and review.**

```matlab
opts = struct('Crosswalk', 'D:\MIM\MASH\crosswalk_2026-10_PHI.csv', ...
              'DenyListFile', 'D:\MIM\MASH\deny_names_PHI.txt');
report = mlphibroker.SafeHarbor.run(root, outRoot, opts);
```

dcm2niix is resolved as `opts.Dcm2niixExe`, then the environment variable `MLPHIBROKER_DCM2NIIX`,
then `PATH`; pin it with the variable and nothing else on the machine is used or touched. Before
anything leaves the PHI zone, read `<outRoot>\shdeid_batch_report.json` (`refused`, `quarantined`,
`dropped_key_names`, `dcm2niix_version`), look into every `quarantine\` folder, and open a sample
of sidecars and file names.

**Outputs** per session, under `<outRoot>/<sub>/<ses>/`:

| File | Content |
|---|---|
| `<sub>_<ses>_trc-<token>[_run-NN]_proc-shdeid_pet.nii.gz` + `.json` | PET (dynamic or static); sidecar with `times`, `taus`, `timesMid` (s), `halflife`, `DecayCorrected`, `DecayCorrectionZeroTime` from `scan_start`, `AdminFromScanStart_s`, `TracerRadionuclide`, body weight, reconstruction keys |
| `<sub>_<ses>[_run-NN]_proc-shdeid_ct.nii.gz` + `.json` | CT with acquisition parameters |
| `<sub>_<ses>_roi-<name>[_run-NN]_proc-shdeid_mask.nii.gz` + `.json` | one uint8 mask per RTSTRUCT ROI on the referenced image grid |
| `<sub>_<ses>_shdeid_report.json`, `<outRoot>/shdeid_batch_report.json` | counts only |
| `quarantine/` | any pair whose name or sidecar failed the date, clock-time, dated-session or deny-list scan |

Subject codes accepted by default: `sub-108xxx` (CCIR_01211), `sub-ECL1i001`-style (MASH, DOTA-ECL1i)
and `sub-9xxxxx` (synthetic); `opts.SubjectPattern` (a regex) admits another project's range. Labels are
BIDS alphanumerics, so `sub-ECL1i-001` is refused. For DOTA-ECL1i the nuclide ([68Ga] or [64Cu]) is read
from the DICOM `RadionuclideHalfLife`, never assumed from the name; the token becomes `trc-gadotaecl1i` or
`trc-cudotaecl1i` accordingly.

## How de-identification happens

dcm2niix is a converter, not a de-identifier. With `-ba y` it still writes the acquisition clock
time, `TimeZero`, serial numbers, station and institution names, and the clock time again in the
NIfTI header `descrip`. The pipeline therefore:

1. converts one series at a time with `dcm2niix -b y -ba y -z y -t n -f "<sub>_<ses>_ser-%s"`
   (never `%t`, `%n`, `%i`);
2. keeps **only** the sidecar keys on `mlphibroker.SidecarPolicy.ALLOW` (fail-closed) and counts
   every dropped key name in the report;
3. reads the administration offset from the DICOM headers (`dicominfo`, header only) and writes it
   as seconds from scan start before any clock value is discarded;
4. resolves the tracer token from the radiopharmaceutical **name and** the DICOM half-life jointly
   (`mlphibroker.TracerTable`; the isotope is never inferred);
5. zeroes `db_name`, `descrip` and `aux_file` in the NIfTI-1 header with voxel bytes untouched
   (`mlphibroker.Nifti1`);
6. rasterises RTSTRUCT contours with `dicomContours`/`createMask` on the referenced series' first
   time frame, places the mask on the dcm2niix output grid through that file's sform, and writes it
   with the reference's own NIfTI header, so mask and PET share one grid and affine;
7. scans every output name and sidecar for date, clock-time, dated-session and deny-list shapes and
   quarantines any hit; reports carry counts only and refuse to be written if they would carry a
   date shape.

## Requirements on MATTA

| Need | Component | Used for |
|---|---|---|
| required | MATLAB R2022b or newer | `arguments` blocks, `jsonencode` PrettyPrint, `gunzip`/`gzip`, tables |
| required | Image Processing Toolbox | `dicomCollection`, `dicominfo`, `isdicom`, `dicomreadVolume`, `dicomContours`, `createMask`, `niftiread`/`niftiwrite` |
| not needed | Medical Imaging Toolbox | replaced by a byte-level NIfTI writer that reuses the converted reference's header and sform (and `medicalVolume` crashes on PET series lacking `SeriesType`) |
| external | [dcm2niix](https://github.com/rordenlab/dcm2niix) Windows release, pinned | PET and CT voxel conversion |
| not needed | Statistics, Parallel Computing, Signal Processing | nothing here uses them |

Never run this inside a Claude Code session: `SafeHarbor.run` refuses when `CLAUDECODE` is set,
except for `sub-9xxxxx` synthetic fixtures with `opts.SyntheticTest = true`.

## Tests

```matlab
addpath('src'); results = runtests('test/+mlphibroker_unittest'); table(results)
```

`Test_SafeHarbor` runs the whole batch on the synthetic fixture and needs dcm2niix; it is skipped
(not passed) otherwise. dcm2niix is resolved in this order everywhere in the package:
`opts.Dcm2niixExe`, then the environment variable `MLPHIBROKER_DCM2NIIX`, then `PATH`. Set the
variable to your pinned copy and other installations (for example MRIcroGL's bundled dcm2niix)
are never used and never touched.
`Test_PublicSafety` fails if any tracked text file carries a real subject code, a dated session
label or an e-mail address.
